## 第一步：下载与检查（已完成）

来源：[GroupLens 官方页面](https://grouplens.org/datasets/movielens/100k/)。在项目根目录执行：

```bash
mkdir -p data/raw
curl --fail --location --output data/raw/ml-100k.zip https://files.grouplens.org/datasets/movielens/ml-100k.zip
python scripts/inspect_movielens.py
```

脚本检查 ZIP 的 CRC，只提取评分和官方 README，保存本地 inspection.json。
SHA-256 记录本次下载版本，尚未与官方摘要比对。数据不提交 Git，也不重新分发；使用条件见下载包内官方 README。

`u.data` 是制表符分隔的四列：用户 ID、电影 ID、评分、Unix 秒级时间戳。原始文件并非按时间排序。

## 如何进入 Brainstorm 上下文

任务：根据过去喜欢的电影，对候选电影排序。首版只使用用户/电影 ID 和正反馈，不使用属性或电影类别。未交互不等于明确不喜欢，负采样是训练近似。

任务说明与训练集统计将进入 System KB；留出测试标签与结果不进入 agent。当前全量统计用于开发时确认协议，不是基线指标或优化收益证据。

## 第二步：固定划分与 ID 映射（已完成）

```bash
mini-agentx prepare-data --config configs/baseline.toml
```

1. 校验四列、评分范围、ID 和时间戳，重复用户—电影交互直接报错。
2. 过滤评分小于 4 的记录；至少三条正反馈的用户才进入实验。
3. 每用户按 `(timestamp, 原始电影 ID)` 升序排序，最后一条作测试，倒数第二条作验证，其余作训练。时间相同的记录只保证稳定次序，不声称严格时间先后。
4. 仅用训练集建立用户与电影字典，原始 ID 按升序映射到从 0 开始的连续 ID。
5. 验证/测试中训练集未见的电影直接排除，不移动回训练，不用留出数据建立词表。
6. 保存 CSV、ID 映射和 manifest，摘要覆盖原始评分、协议、划分和映射文件。seed 不参与确定性的排序划分。

这是逐用户时间留出，不是全局时间切分；本项目使用固定协议作教学比较。

### 输出

本地 `data/processed/movielens-100k-v1/`：

- train.csv、validation.csv、test.csv：user_id、item_id、timestamp。
- id_maps.json：数组下标为新 ID，值为原始 ID。
- manifest.json：数据协议、统计、各文件 SHA-256 与数据版本。

ID 词表包含 942 个用户、1,423 部训练电影；正反馈不足的用户排除 1 个。

| 划分 | 交互数 | 冷物品排除数 |
| --- | --- | --- |
| 训练 | 53,491 | 不适用 |
| 验证 | 935 | 7 |
| 测试 | 925 | 17 |

排除冷物品后验证和测试的用户数量可以不同；评估器必须按各自可评估用户报告均值。验证被排除的用户也可能有有效测试记录。
